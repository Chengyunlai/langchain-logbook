# 把 Posts 改造成按依赖阅读的课程路线

Status: resolved
Triage: ready-for-agent
Type: task
Blocked by: 19

## Why

文档站原本沿用通用博客模板，按发布日期倒序展示教程、Mini DeerFlow 专题、最终实战、源码导读和发布手册。新增内容发布日期较新后，Capstone、DeerFlow 导读与维护资料出现在第 01 章之前；列表摘要又只是重复标题，读者无法判断从哪里开始、每一章要建立什么能力。单篇底部的 Previous/Next 同样按日期跳转，进一步破坏课程依赖顺序。

## Work

- 建立独立于发布日期的课程清单，显式记录阶段、顺序、内容类型和学习结果。
- 将 Posts 页面改为按知识依赖分组的中文学习路线。
- 为每个阶段解释学习目标、适合读者和进入条件；为每篇内容解释“学完你能做什么”。
- 把附录、版本策略和发布手册移出线性主线，标记为按需参考。
- 让首页入口、面包屑、顶部导航和单篇前后导航使用同一课程语言与顺序。
- 保留课程清单与生成内容的一致性门禁，新增或遗漏内容时构建必须失败。

## Acceptance

- 学习路线从课程总览开始，依次经过增强模型层、Agent 封装层、Graph 编排层、Agent 工程层、Capstone 与 DeerFlow 源码导读。
- 第 01–03 章在页面首屏附近可见，并分别说明要理解的核心问题和学完后的能力。
- 发布手册、版本策略和附录不会出现在主线前方。
- 第 01 章的上一步是课程总览，下一步是第 02 章；后续内容按同一清单导航。
- 桌面端与 390 px 窄屏无横向溢出，完整构建、链接、发布契约、测试和教程验证通过。

## Answer

新增 `docs-site/curriculum.json` 作为课程顺序的单一事实源，覆盖全部 22 篇已发布内容。文档生成器从清单写入 `learningOrder`、`learningStage`、`learningGoal` 和 `contentType`；缺少、重复或未列入清单的内容会直接使同步或站点构建失败。通用的日期仍保留给 RSS、Tags 和 Archives，但不再决定课程主线。

Posts 已改名为“学习路线”，按六个主线入口展示：全局地图 → 增强模型层 → Agent 封装层 → Graph 编排层 → Agent 工程层 → Capstone/DeerFlow。每个阶段都有“适合谁”“进入条件”和阶段目标，每篇文章都有“先回答”与“学完你能”；附录、版本与发布资料独立放入“按需参考”。首页只展示课程总览与第 01–03 章，文章底部改为按课程清单生成“上一步/下一步”。

验证结果：Astro check 为 0 error / 0 warning；离线测试 `154 passed, 1 skipped`；教程漂移 `0/0/0`；workflow 契约、32 页静态构建、22 页 Pagefind 搜索索引、站内链接和发布契约均通过。真实浏览器复核了桌面与 390×844 窄屏，页面宽度等于视口宽度且无溢出；第 01 章导航指向课程总览与第 02 章。
